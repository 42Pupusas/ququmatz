# ququmatz kernel-surface roadmap

## Purpose

`AUDIT.md` covers soundness of what already exists. This document covers
*coverage*: which parts of the `io_uring` UAPI (opcodes, register ops, setup
flags, feature bits, per-op tunables) this crate does not yet expose, and the
order to close those gaps in.

Baseline comparison: `include/uapi/linux/io_uring.h` at `torvalds/linux`
master, against `src/types/opcodes.rs`, `src/types/ring_ctrl.rs`,
`src/types/sendrecv.rs`, and the `src/op/*` builders, surveyed 2026-09-11.

## How to read the tables

- **Effort**: S (one opcode/flag, mechanical, follows an existing pattern in
  the same file), M (new field plumbing, a new owned-state wrapper, or a
  handful of interacting flags), L (new subsystem: new mmap region, new
  registration protocol, new ownership model).
- **Value**: how much this unlocks for realistic users of a zero-dep io_uring
  crate — throughput/latency wins, or common-case API completeness — versus
  being a rarely-touched corner of the UAPI.
- **Rank** is Value-weighted first, Effort-broken ties second: cheap+useful
  things go first, expensive+niche things go last. Within a tier, order is
  the suggested execution order.
- Every item must ship per the standing rules: its own module/struct, no
  free functions, tests + clippy + build in every feature combination before
  moving to the next line.

| 17 | ~~`IORING_OP_FIXED_FD_INSTALL`~~ **Done** | M | Med | Promotes a slot already in the ring's registered-file table (opcode 54, Linux 6.8+) to a real process file descriptor — the reverse of a direct open/socket/accept, which install *into* the table. Confirmed against `io_uring/openclose.c`'s `io_install_fixed_fd_prep`/`io_install_fixed_fd`: the SQE always carries `IOSQE_FIXED_FILE` (the kernel rejects the request outright without it, since the point is naming a table slot rather than a descriptor), `off`/`addr`/`len`/`buf_index`/`splice_fd_in`/`addr3` must all be zero, and the only real argument is `install_fd_flags` (aliasing `op_flags`), which accepts a single bit — `IORING_FIXED_FD_NO_CLOEXEC` — to keep the installed descriptor open across `execve` instead of the `O_CLOEXEC` default. The call is `receive_fd` under the hood, the same primitive `SCM_RIGHTS` fd-passing uses, which is why the slot itself is left untouched: the file gains a second owner rather than losing its first. Shipped: `Opcode::FixedFdInstall`, `InstallFdFlags` (`types/fs.rs`), `Sqe::fixed_fd_install` (`op/file.rs`, sets `SqeFlags::FIXED_FILE` itself so a caller cannot forget it), and an owned path in the new `owned/fixedfdinstall.rs` module (`PreparedFixedFdInstall`/`PendingFixedFdInstall`/`FixedFdInstalled`) shaped like `PendingCancel`/`PendingMsgRing` — the request itself owns no caller memory, since a slot number and a flags bit are the whole submission — but shaped like `PendingOpen` in what it *produces*: a real descriptor the completion hands to the caller as an owning `File`, so an ignored completion closes rather than leaks it. `PreparedFixedFdInstall::of` takes an existing `DirectSlot` directly, reusing that type's plain zero-based indexing rather than re-deriving the kernel's off-by-one wire encoding, which this opcode has no use for (it names a slot already occupied, not one to allocate). Wired into `OwnedSubmitter::push_fixed_fd_install`. Verified against a real kernel: a direct open installs a tmpfile into an auto-allocated table slot, `fixed_fd_install` promotes that slot to a process descriptor, a plain (non-fixed) `write` through the returned descriptor succeeds, and a `fixed_file` read through the *original* slot sees the same bytes — confirming both that the promotion produces a genuinely independent descriptor and that the slot survives the promotion untouched. |

   before touching `ring/mod.rs`: which array-indexing call sites assume
   the 64/16-byte stride, and how the wide SQE/CQE layouts should be
